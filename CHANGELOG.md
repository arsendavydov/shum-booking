# Changelog

Все значимые изменения в проекте документируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/),
и этот проект придерживается [Semantic Versioning](https://semver.org/lang/ru/).

## [1.0.3] - 2026-02-12

### ✨ Добавлено
- **Информация о rate limiting в `/health/detailed`**:
  - Добавлен раздел `rate_limiting` с текущими настройками лимитов
  - Отображается статус включения rate limiting (`enabled`)
  - Показываются лимиты для API (`api_limit_per_minute`) и аутентификации (`auth_limit_per_minute`)

### 🔧 Исправлено
- **E2E тест обновления токена**:
  - Добавлена задержка перед обновлением токена для гарантии разного времени создания (`iat`)
  - Исправлена проблема с идентичными токенами при быстрых запросах
- **E2E тесты**:
  - Обновлены тесты для использования `Authorization` header вместо cookies (устранено предупреждение о deprecation)

## [1.0.2] - 2026-02-11

### ✨ Добавлено
- **Улучшен Swagger UI для презентации проекта**:
  - Расширенное описание API с markdown форматированием
  - Контактная информация (email, URL поддержки)
  - Информация о лицензии (MIT)
  - Terms of Service
  - Улучшены описания всех тегов API с подробными пояснениями
  - External Documentation со ссылкой на GitHub репозиторий
- **Примеры для всех эндпоинтов**:
  - Добавлены `openapi_examples` для всех POST/PUT/PATCH эндпоинтов
  - Обновлены email-адреса в примерах на домен `async-black.ru`
  - Примеры согласованы с тестовыми данными из `fill_database.py`

### 🔧 Исправлено
- **Тест проверки подделанного JWT токена**:
  - Улучшена обработка исключений в `AuthService.decode_access_token`
  - Добавлена проверка структуры токена (3 части)
  - Явно указана проверка подписи через `verify_signature=True`
  - Исправлен способ подделки токена в тесте для более корректной проверки

## [1.0.1] - 2026-02-11

## [1.0.0] - 2026-02-10

### 🎉 Первый релиз "Grand Opening"

#### ✨ Добавлено
- **Полноценный CI/CD pipeline в GitHub Actions**:
  - Автоматическая сборка Docker образов
  - Деплой в K3s кластер
  - Интеграция тестов перед деплоем
- **Интеграция тестов в CI/CD**:
  - Линтинг кода (Ruff)
  - Проверка типов (Pyright)
  - Unit-тесты (Pytest)
- **Проверка готовности всех компонентов после деплоя**:
  - Мониторинг статуса всех подов (FastAPI, Celery, Nginx, Postgres, Redis)
  - Health checks для всех endpoints (`/ready`, `/live`, `/health`)
- **Безопасная конфигурация**:
  - Все переменные окружения загружаются из `.prod.env` на сервере
  - Убраны все дефолтные значения для критичных переменных
  - Автоматическое определение `imagePullSecret` на основе registry

#### 🔧 Исправлено
- Ленивая инициализация `RedisManager` для возможности запуска unit-тестов без Redis
- Условная проверка `TEST_PASSWORD` - не требуется для unit-тестов
- Добавлены минимальные переменные окружения для инициализации `Settings` в тестах
- Исправлены аннотации типов в `src/__init__.py` для корректной работы Pyright

#### 🏗️ Инфраструктура
- Развертывание на K3s кластере
- Все компоненты работают в production:
  - FastAPI приложение
  - Celery worker для фоновых задач
  - Nginx как reverse proxy
  - PostgreSQL база данных
  - Redis для кэширования и rate limiting
- SSL/TLS сертификаты через cert-manager и Let's Encrypt
- Приложение доступно по адресу: https://async-black.ru/apps/shum-booking/docs

#### 📊 Метрики
- Prometheus-совместимые метрики на `/metrics`
- Версия приложения в метриках: `1.0.0`
